### Docker :)
1) A Docker container (like spark-master on my mac for example) has its own filesystem and network. We have to explicitly copy over files if the container must use them; we must also bind ports (e.g. 8080:8080) if we want to access them through host machine.

2) Docker can EAT up disk memory if you are careless with your build practices (like I was). Important to understand what happens in each step of the process Dockerfile -> Docker Image -> Docker Container!

    - Remove dangling images, stopped containers, unused networks/volumes
    docker system prune -f

    - Remove all unused images (be cautious — will remove unreferenced ones)
    docker image prune -a -f

    - Clean up unused volumes (they stick around even if containers are gone)
    docker volume prune -f

    - du -sh ~/Library/Containers/com.docker.docker/Data/*

### Spark :)
1) SPARK_LOCAL_IP and SPARK_PUBLIC_DNS

2) The spark **workers** spawn **executors** and the spark **coordinator** is independent of the spark **driver**.

3) It is really important (borderline all that you need to do) to properly set the Spark environment variables in *conf/spark-env.sh*.
