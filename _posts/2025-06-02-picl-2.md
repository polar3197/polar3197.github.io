### Docker

Two critical lessons I learned:
1) A Docker container (like spark-master on my mac for example) has its own filesystem and network. We have to explicitly copy over files if the container must use them; we must also bind ports (e.g. 8080:8080), and define the network to use if we want to successfully communicate between containers on the Local Area Network.

2) I ran into an ephemeral bug where somehow Docker ATE UP all my disk memory. It hasn't happened since I cleaned my Docker storage files and started again, but I believe if you are careless with your build practices (like I was then you can waste lots of memory. These commands are useful for diagnosing the memory usage in your Docker system.
    * `docker system prune -f # Remove dangling images, stopped containers, unused networks/volumes`
    * `docker image prune -a -f # Remove all unused images (be cautious — will remove unreferenced ones)`
    * `docker volume prune -f # Clean up unused volumes (they stick around even if containers are gone)`
    * `du -sh ~/Library/Containers/com.docker.docker/Data/* # check memory usage `
